---
title: Slice location
description: Read the module, feature and slice of a command or query on the backend and from its generated proxy.
---

Every command and query has a slice location: the module, feature and slice it belongs to. Arc resolves it from the same namespace mapping that places the generated proxy, so error handling, diagnostics and support tooling can say where a failure came from without any extra configuration.

## How it is resolved

The location comes from the namespace of the type that owns the command or query: the command type for a model-bound command, the read model for a model-bound query, and the controller for controller actions.

1. When the namespace equals or is nested under a [namespace root](namespace-roots.md), the segments below the longest matching root are used.
2. Otherwise the leading segments set by [`CratisProxiesSegmentsToSkip`](basic.md#namespace-segment-skipping) are skipped.
3. Without a matching root, the `Cratis.API` namespace prefix is removed before skipping, exactly as for the output folder, so the folder and the slice location never differ.
4. Of the segments that remain, the first is the **module**, the last is the **slice**, and those in between are the **feature**, joined with a period.

When fewer than three segments remain, the deepest parts are filled and the rest are empty strings, never null.

With the namespace root `MyApp.Features`:

| C# namespace | Module | Feature | Slice |
| --- | --- | --- | --- |
| `MyApp.Features.Billing.Invoices.Pay` | `Billing` | `Invoices` | `Pay` |
| `MyApp.Features.Billing.Invoices.Recurring.Pay` | `Billing` | `Invoices.Recurring` | `Pay` |
| `MyApp.Features.Invoices.Pay` | _(empty)_ | `Invoices` | `Pay` |
| `MyApp.Features.Pay` | _(empty)_ | _(empty)_ | `Pay` |
| `MyApp.Features` | _(empty)_ | _(empty)_ | _(empty)_ |

The namespace root's `Folder` only affects where files are written; it is never part of the slice location.

## Configuration

There is nothing extra to configure. The Arc build emits the `NamespaceRoot` items and the `CratisProxiesSegmentsToSkip` property of a project as assembly attributes, `[assembly: SliceNamespaceRoot("MyApp.Features")]` and `[assembly: SliceNamespaceSegmentsToSkip(1)]` from `Cratis.Arc.Slices`, so the runtime reads the same values the proxy generator does:

```xml
<PropertyGroup>
    <CratisProxiesSegmentsToSkip>1</CratisProxiesSegmentsToSkip>
</PropertyGroup>
<ItemGroup>
    <NamespaceRoot Include="features" Namespace="MyApp.Features" Folder="features" />
</ItemGroup>
```

Arc reads the attributes from the assembly that declares the type. When that assembly declares neither, for example a class library whose proxies are generated by the web project, Arc falls back to the entry assembly. A project that does not build with the Arc MSBuild targets can declare the attributes itself.

## On the backend

`CommandContext.SliceLocation` and `QueryContext.SliceLocation` hold the location of the executing command or query. Filters receive the context directly; other components can read it from `ICommandContextAccessor.Current` or `IQueryContextManager.Current`.

The two contexts get the value differently. A `CommandContext` carries the command type, so it resolves the location from that type the first time you read it, and a context you construct yourself reports the right location too. A `QueryContext` carries only the query name, so the query pipeline and the MVC action filter, which know the read model or controller type, resolve the location and set it on the context. A `QueryContext` you construct yourself carries `SliceLocation.NotSet` unless you set it.

This filter tags the current trace with the slice the command belongs to:

```csharp
using System.Diagnostics;
using Cratis.Arc.Commands;

public class SliceLocationTracingFilter : ICommandFilter
{
    public Task<CommandResult> OnExecution(CommandContext context)
    {
        Activity.Current?.SetTag("arc.slice_location", context.SliceLocation.ToString());
        return Task.FromResult(CommandResult.Success(context.CorrelationId));
    }
}
```

`SliceLocation` (`Cratis.Arc.Slices`) is a record of the concepts `ModuleName`, `FeatureName` and `SliceName`; an empty part equals its `NotSet` value. Its `ToString()` joins the parts that are set with `/`, for example `Billing/Invoices/Pay`. `SliceLocation.For(type)` resolves the location of any type, and `SliceLocation.NotSet` is the location where every part is empty, which is also what a hand-constructed `QueryContext` carries unless you set it.

## In the frontend

Every generated command and query proxy declares its location as a static member, resolved when the proxy was generated:

```typescript
import { SliceLocation as ArcSliceLocation, PropertyDescriptor } from '@cratis/arc/reflection';

export class PayInvoice extends Command<IPayInvoice> implements IPayInvoice {
    static readonly sliceLocation: ArcSliceLocation = new ArcSliceLocation('Billing', 'Invoices', 'Pay');
    readonly route: string = '/api/billing/invoices/pay';
    // ...
}
```

The generated proxy imports Arc's type under the `ArcSliceLocation` alias, so a type of your own named `SliceLocation` can be used by the same proxy without a duplicate identifier.

Read it from the class, from a type you only hold as a value, or from an instance:

```typescript
import { SliceLocation } from '@cratis/arc/reflection';
import { PayInvoice } from './generated/Billing/Invoices/Pay';

const fromClass = PayInvoice.sliceLocation;
const fromType = SliceLocation.ofType(PayInvoice);
const fromInstance = SliceLocation.of(new PayInvoice());

console.log(fromClass.toString()); // Billing/Invoices/Pay
```

`SliceLocation.of(instance)` and `SliceLocation.ofType(type)` read the static member and return `SliceLocation.empty` when the class declares none. `isEmpty` tells whether any part is known, and `equals(other)` compares two locations part by part. Instances have no `sliceLocation` member: a command with a property named `SliceLocation`, or a query with a parameter of that name, gets a generated `sliceLocation` accessor of its own, and an inherited member of the same name would not compile.

In React, components read the slice they are rendered in with `useSliceContext()`. See [slice context](../../../../frontend/react/slice-context.md).

## Upgrading

Regenerated proxies import `SliceLocation` from `@cratis/arc/reflection`, so upgrade the `@cratis/arc` package to the version that matches the Arc NuGet packages that generate them; an older `@cratis/arc` fails to compile the regenerated proxies. Proxies generated by an earlier version carry no static member and report `SliceLocation.empty` until you regenerate them.
