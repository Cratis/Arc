---
title: "ARC0022: Invalid generated value parameter type"
description: Use a non-nullable type implementing IGeneratable for a generated Handle parameter.
---

## Rule

A `[GeneratedValue]` parameter must be non-nullable and implement
`Cratis.Concepts.IGeneratable<TSelf>` with its own type as `TSelf`.
A static `New()` method alone is not enough. Nullable reference types, `Nullable<T>`,
and by-reference parameters are invalid. **Default severity: Error.**

## Diagnostic example

Compile these alternatives separately with `Cratis.Arc.Core`. The first intentionally
produces ARC0022; `Guid` does not implement the generatable contract.

```csharp
using System;
using Cratis.Arc.Commands.ModelBound;

[Command]
public record AllocateCartId
{
    public Guid Handle([GeneratedValue] Guid cartId) => cartId;
}
```

## Fix

Declare the generation strategy on a non-nullable identifier type:

```csharp
using System;
using Cratis.Arc.Commands.ModelBound;
using Cratis.Concepts;

public record CartId(Guid Value) : ConceptAs<Guid>(Value), IGeneratable<CartId>
{
    public static CartId New() => new(GenerateValue.Uuid());
}

[Command]
public record AllocateCartId
{
    public CartId Handle([GeneratedValue] CartId cartId) => cartId;
}
```

Explicit implementations of `IGeneratable<CartId>.New()` are also supported.
Keep client-supplied identifiers on command properties rather than marking them generated.
See [generated values](../commands/generated-values.md) for resolution and validation behavior.
