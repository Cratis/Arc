Cratis Arc is a full-stack CQRS framework that exposes backend commands and
queries over HTTP and generates TypeScript clients for your frontend. CQRS
separates requests to change data (commands) from requests to read it (queries).
Arc handles validation and authorization around those requests. Write the backend
in C#, Kotlin or Java, or TypeScript; each can generate a typed frontend client.
You can use current-state storage or add event sourcing.

<TopicHero

Keep one feature's command, read model, query, frontend, and specs together as a
vertical slice. Arc exposes the backend contracts over HTTP and generates the
TypeScript callers, so you can work on that feature without maintaining a second
set of request types and HTTP calls. Start with application services or a database;
Cratis Chronicle adds optional event sourcing, and Cratis Components adds optional
React compositions.

</TopicHero>

## Start here

Choose a host below to build your first command and query. On the C# path,
configure proxy generation to produce TypeScript clients from recognized commands,
queries, and included referenced types. A proxy is the generated frontend class
that calls a backend command or query. After a backend contract changes,
regenerate and type-check the frontend to catch structural mismatches. Runtime and
integration checks are still needed; [understand the proxy boundary](./understanding-the-proxy-boundary.mdx)
before connecting your first screen.

## Start an Arc host

Arc runs on ASP.NET Core and Spring Boot; a third implementation for TypeScript
on Node.js is [available from source](/arc/backend/typescript/), with no published npm
package and no claim of full parity. Choose a backend below and compare the
[backend capabilities](./capabilities.md) before relying on a shared example. The shared [HTTP contract](./http-contract.md)
is verified for C# and JVM; TypeScript's coverage is documented separately.

## Commands and queries

Arc supports model-bound commands and read-model query methods. C# also supports
controller-based endpoints; the JVM implementation does not. The command and query pipelines handle dependency injection,
validation, authorization, filters, execution scopes, result conversion, and
HTTP exposure in C# and on the JVM. TypeScript implements a subset of these
capabilities; consult its [capability reference](/arc/backend/typescript/reference/capabilities/).
The [scenario recipes](/arc/scenarios/) show the same task, such
as [validating a command](/arc/scenarios/validate-a-command/), with backend
examples where the capability is available.

Use a request/response query for a single result. Use an observable query when a
screen needs updated results through a subscription, with a configured source of
change notifications. The guides below explain transport, subscription, and
lifecycle behavior. The TypeScript generator creates clients for recognized
commands, queries, referenced types, validation rules, and identity details.

## Frontend contracts

`@cratis/arc` supplies the TypeScript command, query, validation, identity, and
messaging runtime used by generated proxies. `@cratis/arc.react` adds hooks,
command forms, dialog infrastructure, identity composition, and query components. The composed `CommandDialog` used in the tutorial comes from the separate `@cratis/components` package. The optional
React/MVVM package adds view models, dependency injection, route parameters, and
browser abstractions.

[Explore Arc's frontend packages](/arc/frontend/) to choose the TypeScript,
React, or React/MVVM path. Components is separate: applications may use Arc
without Components, and may use the generated TypeScript clients without Arc's
React packages.

## Identity and tenancy

Arc includes [pluggable identity and access behavior](/arc/understanding-identity-and-access/),
identity-detail providers, server-side authorization and role checks, and
frontend identity context. Tenant resolution can use a
header, query parameter, claim, subdomain, fixed value, or development setting
before provider-specific database or namespace mapping — see [tenancy on C#](/arc/backend/csharp/tenancy/)
or [tenancy on Kotlin and Java](/arc/backend/kotlin/guides/ambient-tenancy/).

Frontend visibility helpers do not replace server-side authorization. Tenant
resolution also does not by itself establish isolation for an application or
storage topology.

## Persistence choices

Choose storage for the feature you are building. Commands and queries can use
application services or current-state persistence without an event log; Arc does
not depend on Chronicle. If you want event sourcing, choose the Chronicle guide
for your backend. Each backend integrates with its own ecosystem's data access.

## Inspection, contracts, and testing

Arc can describe registered commands, queries, identity schemas, and OpenAPI
operations at runtime. Repository packages also include analyzers, source
generators, command-scenario testing, proxy-generation checks, Vite helpers, and
Arc-specific ESLint rules.

- [Inspect registered application contracts (C#)](/arc/backend/csharp/introspection/) — commands, queries and identity schemas are also introspectable on Kotlin and Java; a dedicated guide is not yet published
- Generate OpenAPI descriptions: [C#](/arc/backend/csharp/open-api/) or [Kotlin and Java](/arc/backend/kotlin/guides/openapi/)
- Test command behavior: [C#](/arc/backend/csharp/testing/), [Kotlin and Java](/arc/backend/kotlin/guides/testing/), or [TypeScript](/arc/backend/typescript/testing/)
- Review analyzer rules: [C# Roslyn analyzers](/arc/backend/csharp/code-analysis/) or [Kotlin KSP diagnostics](/arc/backend/kotlin/reference/diagnostics/)

:::caution[Check the combination you use]
These are separate packages and integration surfaces. Their existence does not
establish compatibility with every frontend, runtime, persistence provider,
browser, or product version. Check the package manifests and the evidence for the
combination you evaluate.
:::
